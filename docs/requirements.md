# MAG 學習室：產品需求文件

MAG 學習室要把「自己讀一份很難吸收的教材」，變成「有老師陪著，一次弄懂一小步」的學習體驗。學習者帶來教材、說明目標，AI 老師整理教學步驟，在動態白板上逐步書寫與解釋；學習者可以隨時問「這裡不懂」，先釐清，再從原位置繼續。

本文件供產品負責人與實作者共同確認範圍及驗收方式。它描述要做成什麼、目前做到哪裡，以及哪些決策仍未定案。安裝操作請看 [README](../README.md)，已執行的測試請看[驗證紀錄](validation.md)。

**實作基準：** `main` 的程式提交 [`48af72896a41371c4ec405522c1a7aeca47f9fcf`](https://github.com/ynyyzyrf/aiteacher/commit/48af72896a41371c4ec405522c1a7aeca47f9fcf)。下文「目前」指此版本，不代表未來產品只能維持這些限制。

## 1. 問題、目標與第一位使用者

### 要解決的問題

學習者閱讀文件時容易失去注意力，遇到陌生術語容易卡住；一次拿到很長的 AI 回答，也不一定更容易理解。產品要透過短講解、逐步呈現、提問與老師的陪伴感，讓學習者有興趣繼續並參與其中。這是學習情境描述，不是醫療診斷，也沒有宣稱已證明改善學習成效。

### 已確認的方向

- 個人 AI 學習夥伴，體驗受到 Hyperknow 啟發，但不以複製完整商業平台為目標。
- 真正匯入使用者教材，由代理安排教學；不能只展示一門預先寫好的課。
- **大面積、逐步書寫／繪圖的動態白板是核心，不能被普通聊天串取代。**
- 右側持續保留情境提問區，文字先可用，再往即時語音發展。
- 老師要有存在感；具立體感或 3D 的老師角色是產品方向，素材、呈現技術與首版範圍仍待決定。
- 學習者介面使用繁體中文，說明應適合基礎薄弱的人。

### 首輪試用對象

先服務一位 JavaScript 基礎較弱、想入門 TypeScript 的學習者。範例目標是：「先幫我看懂值、變數與函式，再理解 TypeScript 如何檢查型別。」老師不能假定學習者已熟悉參數、回傳值或編譯等術語。

中學生、高中生、大學生與職場人士是曾探索的較廣市場方向，**不是同時推出四套產品的承諾**。擴展科目與族群前，先驗證上述單一情境是否真的教得懂。

### 現階段不做什麼

不把商業課程市集、社群、付費訂閱、學校管理、考試題庫或多租戶平台放進本輪核心驗收。帳號與公開存取方式尚待設計；這不代表最終產品永遠只供本機使用。PDF／PPT、OCR、影片與網址匯入目前不支援，也尚未確認全部納入哪一期。

## 2. 使用旅程與頁面結構

### 一次完整學習

1. **首頁準備：** 輸入想學的目標，附上教材或貼上文字；也可選擇有來源的 TypeScript 範例。
2. **建立課程：** 確認教材可讀，進入教室。老師根據教材與目標安排小步驟。
3. **逐步理解：** 白板逐段出現文字、程式碼或流程圖，搭配簡短講解；學習者可調整速度、暫停、回看，準備好再往前。
4. **隨時打斷：** 點選不懂的白板片段，在右側輸入問題或按「這裡不懂」。原講解停止，老師針對當時可見內容釐清。
5. **接續原處：** 釐清完後，繼續原片段尚未呈現的部分；不跳課，也不重複新增同一片段。
6. **離開與恢復：** 回首頁後能繼續學習；重新整理或服務重啟後，恢復可驗證的已保存進度。

### 首頁

首頁與教室是兩個不同任務空間。首頁承接目標、教材與繼續學習，不在這裡塞入完整教室控制。

| 區域 | 需求 |
| --- | --- |
| 側邊導覽 | 展開／收合是同一頁的兩種狀態；收合後內容區擴展並重新置中，手機可開關導覽 |
| 學習輸入區 | 目標與教材附件整合在同一入口，支援查看／替換附件和貼上文字 |
| 範例提示 | 點選後產生有意義的目標或載入實際範例，不能只有裝飾按鈕 |
| 課程／繼續學習 | 顯示真實存在的課程與進度，不造假修課數、熱門課程、歷史紀錄或社群資料 |
| 能力狀態 | 清楚區分離線測試與真實模型模式；技術細節可展開查看，不搶走學習入口的注意力 |

目前課程卡片以本分頁可找回的課程為主，尚無完整跨分頁、跨裝置課程庫。完整課程庫的搜尋、整理與保存週期另行決定。

### 教室

| 區域 | 需求 |
| --- | --- |
| 主白板 | 保持最大閱讀空間，聚焦當前小步驟；支援文字、程式碼、簡單流程圖，呈現過程可中斷 |
| 步驟與控制 | 呈現目前步驟與進度；提供開始、暫停、接續、讀懂後下一步及已學內容回看，不把不可用控制偽裝成可操作 |
| 右側老師區 | 持續保留角色位置、當前提問對象、問題輸入與釐清內容；提問不需要離開白板 |
| 教材來源 | 可查原文、行號、來源連結與內容指紋，方便核對講解依據 |
| 手機版 | 文字、白板及提問均可操作；小螢幕排版不要求硬塞桌面雙欄，但不可失去情境關聯 |

視覺參考分開使用：首頁是 Hyperknow 同畫面的導覽展開／收合；教室參考 Demo／Muse 的課堂方向。點狀格線、手寫感卡片、奶油色紙面與老師框架可列為待比對方向，**尚不是已驗收的精確視覺規格**。參考圖像素先前無法在驗證環境讀取，沒有完成忠實還原比對。詳見[設計驗收狀態](../design-qa.md)。

## 3. 需求清單與優先順序

優先順序表示實作依賴，不是排期承諾：

- **核心：** 沒有它就無法驗證學習流程。
- **可靠性：** 核心流程可用時必須同時成立的正確性與保護條件。
- **後續：** 已確認的體驗方向，或需要另行決策的擴展；不能用目前替代方案宣稱完成。

「流程已驗證」僅指自動測試、真實 Pi SDK 與固定輸出的離線模型替身（fixture）；「待真實驗收」需要真正模型或人員體驗。

| --- | --- | --- | --- |

| MAT-04 | 核心 | 每步與白板片段引用實際來源；先精確匹配，再僅容許不改意義的排版等價。錯行與換字拒絕，提供有限的行號／原文錯誤資訊 | 機械核對已測試；語意正確性待驗收 |
| LES-01 | 核心 | Pi 根據教材與目標建立循序漸進計畫。首輪先說清 JavaScript 基本概念，再介紹 TypeScript，不假定先備知識 | 規劃工具流程已驗證；真實教案待驗收 |
| LES-02 | 核心 | 一次一小概念，講解建議 60–160 字、硬上限 200 字；201 字拒絕並要求拆分，不以截斷方式通過 | 資料格式限制與提示已實作／測試 |
| LES-03 | 核心 | 解釋術語、使用小例子與簡短理解確認，讓學習者主動決定是否往前；不靠自動連播堆長文 | 手動節奏已實作；參與感與教學品質待驗收 |
| LES-04 | 可靠性 | 附帶 TypeScript 來源筆記可查看官方連結，明確標示非官方翻譯；使用者教材不得自動標為外部可信資料 | 已實作／測試 |

目前匯入範圍為 UTF-8 `.txt`、`.md` 或貼上文字：40–40,000 字元，正規化後最多 65,536 bytes（64 KB）、800 行；學習目標最多 500 字。超限 bytes／行數會回報實際數值。這些是目前可驗收的支援界線，新增格式應另外定義解析、來源定位及失敗情境，不能只增加上傳按鈕。

### 執行安全、用量與錯誤

| ID | 優先 | 要求與可測驗收條件 | 基準版本狀態 |
| --- | --- | --- | --- |
| RUN-01 | 核心 | 全部教學編排使用 Pi：對話、工具回合與取消都由 Pi 整合處理，不能只換模型供應商而保留另一套隱藏教學代理 | 官方 SDK 已整合，工具流程已驗證 |
| RUN-02 | 可靠性 | 操作 UUID 去重、revision 檢查畫面版本；生成 epoch 與工作階段代次阻擋舊結果。重複「下一步」不跳兩步，晚到工具不寫入新白板 | 已實作／測試；目前去重記憶保留最近 200 個操作 ID |
| RUN-03 | 可靠性 | 提問／暫停先凍結本地呈現並取消朗讀，再要求 Pi 停止。停止等待有上限，卡住的工作被隔離與清理，不可永久卡住控制區 | 約 5 秒停止等待；兩個仍卡住的舊工作時拒絕新增生成；已測試 |
| RUN-04 | 可靠性 | 生成逾時、斷網、驗證失敗、無模型或存檔不可恢復要顯示錯誤；保留可讀的既有內容，提供適當重試／重新匯入路徑 | 已有錯誤處理與回歸；一般生成期限 45 秒 |
| RUN-05 | 可靠性 | 每次模型呼叫前檢查本課程預算，包含工具後續回合與失敗／取消；80% 提示，額度不足阻擋新呼叫。重啟不可清空同課程已用額度 | 已實作／測試；保守估算，不是金額上限 |
| RUN-06 | 可靠性 | 白板片段上限可設定，包含釐清片段；達上限顯示原因，不無限追加。fixture 選不到相容目錄時明確失敗 | 已實作／測試 |
| RUN-07 | 可靠性 | 教材、問題均是不可信資料；工具不能執行來源要求、讀寫任意檔案或使用 shell。來源樣式碼以文字呈現，供應商原始錯誤不直接外洩 | 限定工具、資料驗證與錯誤清理已實作 |
| RUN-08 | 核心 | 模式始終可辨識：live 失敗不可悄悄改用 fixture。離線成功只能證明互動與執行流程，不宣稱理解問題 | 已實作／測試 |

目前 `MAG_TOKEN_BUDGET` 預設 200000（可設 1–10000000）；每次預留序列化輸入的 UTF-8 bytes、最多 2048 輸出 tokens 與 1024 緩衝。有效工作階段收到的供應商用量另行記錄，若高於預留則追加計入；低於預留不退款，未知或已隔離工作保留原預留。這是保守的呼叫限制，不是精確 token 帳本、全站配額或美元上限，也不能撤回已送出的請求。`MAG_MAX_BEATS` 預設 80，可設 1–1000。新課程有自己的預算；正式多使用者／費用政策待定。

語音與角色應建立在可中斷的文字流程上，不阻擋核心驗證。是否把朗讀、單次收音與全雙工安排在同一發布版本，需要另行決定。

## 4. 系統責任與資料流

Pi 的指定來源是 [earendil-works/pi 的 coding-agent](https://github.com/earendil-works/pi/tree/main/packages/coding-agent)。目前採官方 `@earendil-works/pi-coding-agent@1.0.2` SDK；這裡的「教學核心」是管理對話、決定工具呼叫與取消的執行流程，不只是模型 API。

```text
首頁：目標 + 教材
  → 後端：格式檢查、原文行號、來源指紋
  → Pi：依教材規劃，呼叫 plan_lesson
  → Pi：呼叫 board_beat，提交短講解 + 對應白板 + 引用
  → 後端：驗證來源／限制，提交有效片段與保存進度
  → 教室：按可見游標逐步呈現
  → 提問：凍結呈現、取消舊生成，帶可見情境回到 Pi
  → 釐清：保持原步驟，回答後接續已保存位置
```

| 責任 | 簡單說明 | 目前位置 |
| --- | --- | --- |
| 教材與來源 | 保留使用者提供什麼、哪些行可引用；不把匯入等同外部查證 | [material.ts](../server/material.ts) |
| 教學對話與規劃 | Pi 保存對話、安排受限制工具回合；`plan_lesson` 建立 2–8 步，`board_beat` 提交一次短講解與白板 | [pi.ts](../server/pi.ts) |
| 進度與中斷 | 決定目前步驟、有效操作、暫停點與哪些舊回應不能再寫入 | [lesson.ts](../server/lesson.ts) |

| 語音介面 | 將聲音輸入接到同一提問流程，處理播放與取消；未來即時服務另行整合 | [voice.tsx](../src/voice.tsx) |

前端使用 React／TypeScript，後端使用 Node.js／Express。這些是目前技術選擇，尚不構成最終雲端架構。

[Mentora](https://github.com/hamzaali81/mentora) 曾作為前端與白板參考；目前只重用 MIT 授權的箭頭幾何函式，沒有採用它的教學代理或整套服務。詳見[選型紀錄](reuse.md)及[保留的授權](MENTORA-LICENSE.txt)。未來重用仍須核對授權與耦合，不能視為已決定整套導入。

## 5. 資料、隱私與保存

### 現在會保存什麼

伺服器本機的 `.mag-lessons/` 保存教材全文、行號／指紋、目標、計畫、白板片段與已確認游標、提問、操作去重資料及用量。可用 `MAG_DATA_DIR` 改目錄。檔案建立時使用私人權限並排除 Git；實際保護仍依作業系統與部署環境，**不代表資料已加密**。

瀏覽器 `sessionStorage` 只保留本分頁課程 ID。ID 用來找到課程，不等同帳號身分驗證；目前只適合可信的單人本機環境。Pi 重建取得已提交內容摘要，不保存完整內部模型狀態。

### 保留與清理規則

- 最多載入 20 堂課；一小時無活動的有效存檔在下次服務啟動時清除，記憶體閒置課程在下次匯入時清除。這不是準時一小時立即刪除的排程；持續讀取也會更新活動時間。
- 換教材會刪除前一堂存檔；損壞、模式不同或超過載入上限的資料不會載入。損壞檔不自動刪除。
- 關閉分頁後，目前不提供完整找回課程清單；跨裝置同步及長期保留政策待定。
- 要立即清空本機教材，可先停止服務再刪除設定的資料目錄。面向一般使用者的產品內刪除／匯出操作需另定範圍。
- 書寫約每 250ms 提交 checkpoint，離頁時再嘗試保存。斷網、強制關閉或斷電可能丟失最後幾個字的進度，只能還原已確認位置；不宣稱零資料損失。

### 對外傳輸與憑證

真實教學會把教材與問題交給已設定的模型供應商，介面／文件須讓使用者知道。瀏覽器語音辨識也可能由瀏覽器廠商遠端處理；未來語音方案需明確界定音訊傳輸與保留。

模型憑證只在伺服器受保護設定或被 Git 忽略的私人 `.env` 中配置，不進前端、聊天、公開文件或儲存庫。公開部署前必須決定存取控制、教材隔離、傳輸保護、刪除方式和供應商資料政策；目前不能把本機課程 ID 當成正式授權機制。

## 7. 驗收情境

### 可重現的功能驗收

| 場景 | 操作與期待結果 | 對應需求 |
| --- | --- | --- |
| 自訂教材 | 上傳非 TypeScript 的有效筆記、輸入目標；原文與來源可查，計畫／白板引用該份資料 | MAT-01–04、LES-01 |
| 格式邊界 | 分別測試有效檔、無效 UTF-8、PDF、超過 64 KB 與 800 行；拒絕項目顯示原因與適用的實際數值 | MAT-03 |
| 引用正確 | 相同字詞的允許排版變化通過；同引文指錯行、換掉關鍵字均拒絕。語意判斷另由人工驗證 | MAT-04 |
| 短講解與圖文 | 200 字接受、201 字拒絕；四節點唯一錨點講到第二個時只顯示兩個；重複／缺失錨點拒絕 | LES-02、BRD-01–03 |
| 打斷與追問 | 白板寫到一半問「這裡不懂」，原片段停止；再追問仍在同一步，接續同一片段與位置 | ASK-01–02、RUN-03 |
| 回看與首頁 | 回看前一步不新增片段；回首頁先停，再從真實卡片返回同課程 | UI-01、NAV-01 |
| 恢復與隔離 | 暫停後重整精確恢復已確認游標；書寫中重整恢復最後成功 checkpoint。偽造瀏覽器白板不採信，過期 beatId 不改新片段 | SAVE-01、SAVE-03 |
| 服務重啟 | 保存後重啟同模式／目錄；有效來源與課程還原，損壞引用拒絕；提問仍包含重啟前可見內容 | SAVE-02、MAT-04 |
| 重複與晚到結果 | 同 UUID 下一步不重做，過期版本不跨步；模擬卡住 Pi，停止有界，晚到結果不能改接續後內容 | RUN-02–03 |
| 限制與失敗 | 小預算開始／重試均受限，80% 有提示；達片段上限不再追加；無模型／斷網不假裝成功，也不切 fixture | RUN-04–08 |
| 聲音分層 | 先用實體瀏覽器確認朗讀與停止、收音權限拒絕及文字退路；全雙工與逐字同步另行驗收 | VOI-01–03 |

### 真實模型的 TypeScript 教學驗收清單

使用既有授權模型與可查看的來源，由驗收者逐項記錄「通過／未通過／無法判定」及對應片段。自動測試通過不能替代以下觀察，也不預設達成率或學習成效數字。

- **先備知識：** 面對「我不懂變數／參數」能先用小例子解釋，再回到 TypeScript，不用更多未解釋術語回答。
- **內容準確：** 正確區分 JavaScript 執行與 TypeScript 靜態檢查、型別推斷與註記；不把型別註記當成網路資料的執行時驗證，不誤稱每個型別錯誤都必然阻止 JavaScript 輸出。
- **來源含義：** 不只看引文是否存在，還要核對它是否真的支持該講解；補充例子明示是例子，教材不足時承認不足，不補造來源。
- **閱讀節奏：** 每片段只處理一小概念，短句可理解，有合適的小例子與理解確認；停下來提問不造成大量新內容湧入。
- **白板一致：** 解釋的程式碼、節點及指涉對得上當時已顯示的內容；沒有講尚未出現的圖，程式碼例子本身也要人工核對。
- **情境釐清：** 選中特定片段只問「這裡不懂」，老師能針對該處換種說法；追問後仍回到原學習線，不另開完整課程。
- **接續與重啟：** 釐清後不重複原白板，後續說明能自然承接；服務重啟後基於保存摘要回答，不假裝記得未保存的內容。
- **學習者參與：** 學習者能用自己的話說明眼前例子，或明確指出哪裡仍不懂；把觀察作為改善依據，不當成已完成的使用者研究結論。

## 8. 風險、依賴與待決策

| 待決策／依賴 | 為什麼影響驗收 | 尚需確認 |
| --- | --- | --- |
| 真實模型設定 | 沒有可用 live 模型就無法證明教學與接續品質 | 既有授權供應商／模型、受保護配置及可接受用量政策；不在文件中放金鑰 |
| 語音方案 | 瀏覽器支援、辨識、播放與即時打斷是不同問題 | 全雙工供應商、音訊資料處理、降級規則、同步／延遲驗收界線 |
| 老師角色 | 靜態圖示無法證明立體老師的陪伴體驗 | 2.5D／3D／其他呈現方式、授權資產、表情動作、裝置成本與首版範圍 |
| 參考圖可讀性 | 沒有實際像素就不能驗收還原程度 | 可合法讀取的實際參考與設計比較；不可用描述或功能截圖冒充完成 |
| 公開使用方式 | 現在只有本機服務，沒有產品入口及帳號隔離 | 部署位置、公開／受邀使用、身份驗證、資料隔離與運維責任 |
| 長期學習資料 | 本分頁短期進度不同於完整個人課程庫 | 關閉分頁後找回、跨裝置、保留週期、匯出／刪除及資料備份 |
| 更多教材格式 | PDF／PPT 等解析會改變來源定位與錯誤處理 | 實際優先格式、解析品質與引用驗收，尚無全部格式同時上線承諾 |
| 教學與產品成效 | 引用檢查不能消除幻覺，流暢動畫不等於理解 | 先完成真實試教，再決定觀察方法與成效指標，不先杜撰數字 |

未決項目需要補上可檢查的決策與驗收條件再進入對應階段。既有本機保存、瀏覽器語音與靜態老師是當前技術切片，不應被誤寫為最終產品的永久限制或已完成目標。
